## Context

OpenCode V1 (版本 1.18.5) 的插件自动发现机制不稳定，显式配置插件路径可正常工作。安装脚本当前的注释声称"无需手动注册"，但实际测试证明这是误导性的。

## Goals / Non-Goals

**Goals:**
- 确保插件安装后能被 OpenCode V1 正确加载
- 更新文档和注释，准确反映 OpenCode V1 的行为
- 简化用户配置步骤

**Non-Goals:**
- 不修改 OpenCode 本身的自动发现机制
- 不迁移到 OpenCode V2（那是另一个变更）

## Decisions

### 决策 1：主动注册插件到配置文件

**选择**：在 `install-local.sh` 和 `install-global.sh` 中主动将插件路径写入 `.opencode/opencode.jsonc`

**理由**：
- 显式配置已验证可工作
- 避免用户手动编辑配置
- 与 OpenCode V1 的实际行为一致

**替代方案**：
- 继续依赖自动发现 → 已证明不可靠
- 提示用户手动配置 → 增加用户负担

### 决策 2：更新配置字段名

**选择**：使用 `plugin`（单数）而非 `plugins`（复数）

**理由**：
- OpenCode V1 使用 `plugin` 字段
- 当前版本是 1.18.5（V1），非 V2

### 决策 3：更新脚本注释和用户文档

**选择**：移除误导性的"无需手动注册"声明，明确说明显式配置是必要的

**理由**：
- 避免误导用户
- 准确反映当前 OpenCode V1 的行为

## Risks / Trade-offs

**风险 1：OpenCode V2 发布后配置格式不兼容**
- **缓解**：在 README 中注明这是针对 OpenCode V1 的配置，未来迁移到 V2 时需更新字段名为 `plugins`

**风险 2：配置文件被其他工具覆盖**
- **缓解**：脚本检查配置文件是否已注册插件，避免重复写入

**权衡**：牺牲"零配置"的简洁性，换取稳定性和可靠性
